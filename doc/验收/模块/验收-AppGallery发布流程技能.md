## 技能发现与资源路由

### 素材或合规任务触发

- 验证步骤：检查 `SKILL.md` frontmatter 是否仅描述触发条件，并覆盖签名、图标、截图、本地化、隐私、分级、版权、备案、上传、自检和提交。
- 预期结果：description 同时说明能力与 `Use when` 触发场景；主入口要求完整读取发布流程与字段清单，故障时读取排障文档。
- 验证命令：`pwsh -NoProfile -File .\scripts\test-skill-documentation.ps1`。

## 公开分发说明与元数据

### GitHub README 与 Codex 展示一致性

- 验证步骤：检查 `README.md` 的用途、适用场景、安装、调用示例、资源导航、安全边界、验证命令和许可证；检查 frontmatter `description` 是否同时说明能力和具体触发场景；核对 `agents/openai.yaml` 的展示名、25–64 字符短描述和显式包含 `$publishing-harmonyos-appgallery-skill` 的默认提示；检查项目 `AGENTS.md` 与 `.gitignore`。
- 预期结果：GitHub 首页能直接说明如何安装和使用；HarmonyOS/HarmonyOS NEXT、AppGallery Connect、签名 APP、商店资料、隐私合规、审核整改和状态验证均可触发；项目入口指向真实资源与验证命令；真实 `.env`、签名材料和 `.app`/`.hap` 不被跟踪。
- 验证命令：`pwsh -NoProfile -File .\scripts\test-skill-documentation.ps1`；`python -X utf8 "$env:USERPROFILE\.codex\skills\.system\skill-creator\scripts\quick_validate.py" .`；`git diff --check`。

## 发布证据链

### 签名 APP 与平台记录绑定

- 验证步骤：从 Git commit、工程级 `assembleApp`、独立验包、SHA-256、上传软件包行、合法性和自检报告依次核对身份。
- 预期结果：`.hap`、`BUILD SUCCESSFUL`、旧报告或“最新一条”均不能替代精确 `.app` 证据；报告时间和身份必须绑定本次上传。
- 验证命令：项目实际发布时运行 `verify-release-package.ps1`，并人工读取当前 AppGallery 软件包记录。

### 状态语义

- 验证步骤：分别检查草稿、预审/审核中、审核通过/待上架和已上架的允许表述。
- 预期结果：只有目标地区商店端真实可见并可安装时才称为已上架。

## 应用信息与素材

### 多语言和素材设备组

- 验证步骤：遍历当前语言列表和门户实际显示的素材设备组，核对名称、图标、介绍、截图/视频和回退说明。
- 预期结果：手机/平板共用 `手机/平板` 素材组；不虚构独立平板槽位，也不遗漏 PC/手表/大屏适用组。

### 图标和截图

- 验证步骤：按 `references/appgallery-form-checklist.md` 核对数量、比例、分辨率、格式、大小、真实渲染、排序、保存和刷新结果。
- 预期结果：上传前发现 UI 缺陷时回到源码与完整重发循环；预览或保存弹窗不单独构成持久化证据。

## 隐私与合规

### 隐私三条证据链

- 验证步骤：分别核对应用隐私说明、隐私声明和隐私标签；检查自定义政策入口、隐私权利入口或托管协议关联。
- 预期结果：三组字段互相一致；两个入口分别可验证但不预设必须使用不同 URL；本地业务数据按具体类型判断个人信息。

### 版权与 APP 备案

- 验证步骤：根据发布地区、设备、版权主体/授权链、网络和服务器事实判定证书、代理材料、备案、境外或单机 APP 路径。
- 预期结果：中国大陆手机版权必选项不遗漏；单机 APP 有代码/权限/运行证据和用户事实确认。

## 提交与发布授权

### 动作时确认

- 验证步骤：检查创建、上传、自检、保存、提交审核、撤销审核和手动发布是否分别授权。
- 预期结果：`继续`、上传授权或保存草稿不推导为提交审核；指定时间后的手动发布需要新授权。

## 审核驳回与重提

### 报告与被审核软件包绑定

- 验证步骤：读取报告提交/生成时间、应用/Bundle/版本、测试环境和报告 ID/URL；用报告、提交快照或平台不可变历史记录识别被审核包，并与当前已选包、本地候选 APP 比较。
- 预期结果：当前已选行不被反向当作提交历史；无法唯一证明被审核包时保持 `UNKNOWN/BLOCKED`。本地另有修复包时只记录为候选；上传新包但版本仍选旧包时结论为 `BLOCKED`。

### 驳回问题矩阵

- 验证步骤：用名称/图标不一致、一句话简介不完整、最低兼容 API 过高、功能场景有限四类问题检查矩阵字段、修复分流和关闭证据。
- 预期结果：包配置或功能问题不能只靠门户文案关闭；功能受时间/账号/外设/数据阻塞时有正常审核可达路径，自测视频不替代真实功能。

### 替换包与重新提交

- 验证步骤：核对新 commit、签名 APP、SHA-256、compatible/target API、上传行、版本选取保存/重载和逐项 `VERIFIED_PORTAL` 证据。
- 预期结果：重提摘要同时列出旧报告/被审核包和新已选包；只有新的动作时授权才允许 `重新提交审核`。

## 文档契约

### 自动回归

- 验证步骤：运行文档契约、`git diff --check` 和 PowerShell Parser。
- 预期结果：关键字段与官方链接存在，无空白错误，全部脚本可解析。
- 验证命令：`pwsh -NoProfile -File .\scripts\test-skill-documentation.ps1`；`git diff --check`；PowerShell Parser 遍历 `scripts/*.ps1`。
