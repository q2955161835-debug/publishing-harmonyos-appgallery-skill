# 发布故障处理

先保留原始错误、命令、退出码和当前 Git/平台状态。不要为赶进度绕过签名、验包、自检或最终确认。

| 症状 | 原因/判定 | 处理 |
| --- | --- | --- |
| `00306054 ... assembleApp task not found` | 在 module 模式调用了工程级任务 | 运行 Hvigor 任务列表确认后，改用 `--mode project ... assembleApp`。 |
| `11014007 Key alias password error` | 别名密码或密钥库密码不正确 | 让用户在本机 DevEco 重新输入；不得从聊天、脚本或日志取回密码。 |
| 上传提示格式不符合 | 选择了 `.hap`、未签名包或错误容器 | 运行工程级 `assembleApp`，验签后上传 `.app`；改扩展名无效。 |
| `BUILD SUCCESSFUL` 但不能发布 | 构建成功不代表签名/Profile/元数据正确 | 运行 `verify-release-package.ps1`，核对三个成功信号和 `pack.info`。 |
| `verify-app` 有额外 warning | 某些可选输出或 APP 外层容器提示不等于失败 | 只在退出码为 0，且 `verify-app success` 和 `Digest verify result: true` 同时出现时通过；否则失败。 |
| Profile 验证失败 | Profile 损坏、类型/证书/Bundle 绑定不对或已失效 | 重新核对 release Profile、证书有效期和 Bundle Name；必要时经授权重新生成。 |
| 浏览器文件选择超时 | 扩展无法控制本地文件选择器或权限不足 | 提示用户手动选择精确 `.app`；之后读取软件包表验证，不能把点击上传等同于成功。 |
| 上传后暂时看不到新包 | 平台仍在解析或页面未刷新 | 等待解析、刷新并按文件名/上传时间核对；不要立即猜测版本冲突或盲目提高 buildVersion。 |
| 同版本存在多个包/报告 | 旧包和旧自检结果仍保留 | 用上传时间、文件名、报告 ID、测试时间、Bundle 和版本建立一一对应。 |
| 自检一直 `检测中` | 云任务仍运行或页面状态陈旧 | 按合理间隔刷新；云任务不会因浏览器断开自动取消。未生成新报告前保持“等待”，不能声明通过。 |
| 自检失败 | 平台发现真实兼容、UX、隐私或性能问题 | 保存报告证据，在本地复现并进入新的修复→验收→签名 APP→验包→上传循环。 |
| ArkTS 警告仍存在 | 可能是可抛异常、弃用 API、重复组件 ID、混淆等 | 分类记录并评估风险；警告不自动等于构建失败，但关键发布风险必须修复或显式接受。 |
| `build-profile.json5` 出现本机路径/凭据差异 | 临时 release 配置未恢复 | 立刻停止提交，恢复原始字节，确认 `git diff --exit-code`；签名材料留在仓库外。 |
| 上传弹窗点击“+”没有文件记录 | 弹窗尚未选择使用场景，或只打开了文件选择器 | 正式发布先选择“测试和正式上架”，再选择精确 `.app`；最后回读新增软件包行。 |
| Chrome 上传返回 `Not allowed` | 浏览器扩展没有本地文件权限或当前上传能力受限 | 不要在 D 盘、工作区和临时目录间反复复制试错；按浏览器能力处理权限，或让用户手动选择，随后读取远端记录。 |
| 图标在手机存在、平板页找不到独立槽位 | 当前官方素材映射中手机和平板共用 `手机/平板` 页签 | 按当前页面与官方文档确认素材设备组；不要臆造平板独立上传，也不要漏掉 PC/手表/大屏等实际页签。 |
| 截图上传失败或提交时提示数量不足 | 数量、方向、分辨率、大小、格式不满足当前素材规范，或素材未保存 | 读取当前上传控件和官方素材规范；检查真实文件元数据，上传要求数量后保存、刷新并复核。 |
| 截图格式合规但画面存在不可见文字/裁切 | 素材制作只检查了文件规格，没有验收真实渲染 | 停止提交，回到源码修复、设备验收、重新签名 APP、验包、上传和自检；禁止只修图掩盖缺陷。 |
| 自定义隐私政策 URL 无法使用 | URL 返回 404、需要登录、是占位页或内容与应用不符 | 填写前实际访问政策和隐私权利两个入口；无有效页面时，经用户确认改用支持范围内的隐私托管。 |
| 隐私托管政策显示“完成”但版本仍缺隐私声明 | 协议已生成但未在待发布版本关联，或关联后未保存 | 回到版本 `隐私声明`，选中精确协议，保存并刷新复核；生成协议不等于版本已关联。 |
| 本地应用的托管政策出现服务器/收集模板措辞 | 标准模板与实际本地数据流没有完全对齐 | 依据真实数据流填写存储地点、期限、删除方式和不联网说明，预览全文；法律确认由用户完成。 |
| 权限隐私说明与 Profile 不一致 | 包声明了受限开放权限，但发布 Profile 未申请或理由/视频缺失 | 核对 `module.json5`、代码场景、Profile 和隐私政策；必要时经授权重建 Profile、重新签名和上传。 |
| 年龄问卷已有计算结果但版本页仍为空 | 只点击了“验证”，没有提交最终分级，或儿童确认未完成 | 完成等级选择、`提交` 和适用的儿童确认，再回版本页读取回写结果。 |
| 备案字段不确定选哪项 | 把“使用本地数据库”误当成自动免备案，或未核对公共互联网服务 | 按官方定义选择中国大陆服务器、境外服务器或单机 APP；用网络权限、代码和运行行为佐证，法律事实由用户确认。 |
| 联系方式看似填完仍无法提交 | 中国大陆账号负责人手机验证码未通过，或把公开客服/隐私联系人误当作审核联系人 | 分别填写审核负责人姓名、手机、邮箱并由用户输入短信验证码；保存后重载复核。 |
| 指定上架时间已过或时区不符 | 复用旧草稿，或只看本地时间没有核对平台 UTC | 重新确认本地时间与平台换算后的 UTC；修改并保存。审核通过后的手动发布需新授权。 |
| 上架自检显示 `待优化` | 合法性可能允许提交，但自检发现风险 | 读取报告异常和日志；不能称为通过。向用户展示驳回风险，由用户决定修复或明确接受风险。 |
| 页面已保存但按钮仍提示缺项 | 草稿字段未持久化或其他区域还有必填项 | 刷新重读页面，逐区检查错误提示、隐私、分级、地区、联系人和版本选取。 |
| 提交确认提示包支持 PC/2in1、应用信息未勾选 | 包支持设备范围大于平台配置 | 回应用信息核对支持设备和实际适配证据；只有明确决定不发布该设备时才按当前页面选择忽略，并记录风险。 |
| 审核说名称/图标不一致，但本地已经改过 | 审核使用了旧包，或 AppScope、EntryAbility、本地化资源、终端与门户只改了其中一处 | 先绑定审核报告和被审核软件包；逐语言、逐设备安装替换包，核对终端名称、图标与 AppGallery 应用信息，再上传、选取、保存并重载。 |
| 一句话简介字数合规仍被判不完善 | 文案只是口号、宽泛收益、关键词组合或残句，没有说明真实功能 | 改为完整功能句，明确用户动作、对象或直接结果；同步核对应用介绍、截图与 release 构建实际能力。 |
| 审核报告称最低适配/API 过高，但本地 compatible API 已降低 | 报告对应旧包、新包未被版本选取，或构建配置没有进入最终 `pack.info` | 读取审核报告身份、失败版本已选包和新 APP 的 `pack.info`，分别核对 compatible/target API；完成兼容测试后上传新包并回读版本选取。 |
| 审核认为功能或使用场景有限 | 核心价值实际不足，或功能被时间、账号、外设、数据条件阻塞，审核会话只能看到记录/静态页面 | 列出干净安装后的核心闭环与审核可达路径；真实能力不足就回到产品开发，前置条件阻塞则提供正常可用入口或受支持审核环境。备注/视频只补充，不替代功能。 |
| 驳回后新包已上传，但失败版本仍显示旧包 | 只完成软件包管理上传，没有在版本选取中选择、保存并重载 | 停止重提；在失败版本选中新包，核对文件名/版本/构建/上传时间，保存、离开重进并回读“已选软件包”。 |
| 报告没有文件名，失败版本当前已选包曾被改过 | 当前页面状态不是提交时的历史证据，无法唯一确定被审核软件包 | 查找报告、提交快照或平台不可变历史记录；仍无法证明时保持 `UNKNOWN/BLOCKED`，不要把当前包倒推成审核包或生成重提摘要。 |
| 用户说“继续” | 只表示继续当前已授权范围 | 可继续读取、验证和保存；最终 `提交审核` 与后续“上线”仍需动作时明确确认。 |

## 诊断输出最低要求

报告失败时给出：失败阶段、字段或素材设备组、原始错误摘要、使用的包/commit/版本、已尝试方案、未执行的高影响动作、当前回退点和下一步。不要泄露签名密码、测试账号秘密、密钥、Cookie、OTP、短信验证码或本机敏感配置内容。
